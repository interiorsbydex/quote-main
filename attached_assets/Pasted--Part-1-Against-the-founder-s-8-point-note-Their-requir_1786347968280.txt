🔴 Part 3 — Three real problems the stress test found
Problem 1: Item identity is broken (most serious)
To diff versions and carry items forward, the system must answer "is this the same item as last version?" Right now it can't reliably:

sheet_row_id is just the row number, and it restarts on every tab. Across 2,222 items there are only 634 distinct values — Xpress row 5 and Xpand row 5 collide.
Row numbers shift when anyone inserts or deletes a row mid-tab. Insert one row at the top of Xpress and all 273 items below look "changed."
Matching on description + tab + room type + unit type + brand gives 2,171 unique out of 2,222 — 51 genuine duplicates remain.
Without fixing this, your change preview would show hundreds of false changes and backporting could grab the wrong item. Fix included in the plan as step 1.

Problem 2: New product lines needed a developer
The sync has the 7 tab names hardcoded. If DeX launches "DeX - Glass" next year, the sync would ignore it or error — violating the founder's point 8. Now fixed: tab discovery becomes dynamic.

Problem 3: No rollback
If an admin publishes a bad V3 (wrong prices pulled from a half-edited sheet), there was no way back. Now added: a Revert action that re-activates the previous version.

Also hardened: version-scoped caching (the current cache is one global object — it would have leaked V2 prices into V1 projects), a concurrency guard so two admins can't collide mid-publish, and confirmation that markup/margin/selling price are all versioned, not just rate.
