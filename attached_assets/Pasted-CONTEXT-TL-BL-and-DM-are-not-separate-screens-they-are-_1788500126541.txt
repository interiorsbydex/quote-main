CONTEXT: TL, BL, and DM are not separate screens — they are user roles. Currently, when Admin creates a new user, the only role option is "Designer." We need TL, BL, and DM added as selectable roles. When a user is created with one of these roles, they should automatically get a role-specific portal/dashboard, without needing separate screens built per role.

OBJECTIVE:
1. Add TL, BL, DM as selectable roles when creating a user in Admin Portal (alongside existing Designer role).
2. When a user is assigned TL, BL, or DM, they see a role-based dashboard showing only relevant projects for their role.
3. Within this dashboard, add filters: Date range (Created Date, start+end) and Created By (multi-select, but only showing team members already assigned to that specific role/team, not everyone in Admin).
4. Both filters must work together (match both conditions at once), and the default view (no filters applied) shows all projects for that role.
5. Separately: display PD and DTL as Team Lead cohort labels in the software, and under each cohort, show the quotations created by team members within that cohort.
6. When a new user is created and assigned as TL, BL, or DM on a project, they must immediately see that project in their profile/dashboard as soon as their account is created — no manual step needed.

SCOPE: Admin user-creation flow (add role field), and a new role-based dashboard view. Do not touch project creation, pricing, or catalog logic.

CONSTRAINTS: N/A must be a valid, selectable option in TL/BL/DM dropdowns for when no assignment applies. Existing users/projects without these roles should not break — treat them as unassigned rather than erroring.

DONE WHEN: Creating a user with role "TL" shows them a dashboard with only their tagged projects, filterable by date range and by team member (multi-select), both filters combinable. PD/DTL cohort labels display correctly with their team's quotations grouped underneath. A brand-new TL/BL/DM user immediately sees their assigned project without any extra step.
